# 可执行计划与任务契约

适用于后续计划；不追认历史未批准的实现。遵循只读 `MASTER_SPEC.md`、
`AGENTS.md` 和已接受 ADR。模板见 [Task Template](tasks/TEMPLATE.md)。

## 1. 交付计划前，Codex 必须查清什么

计划作者负责检查，不把这些检查转交给产品负责人审批：

1. **现状**：实际分支/工作区、依赖 Task 的证据、接口和全部直接调用方。
   “代码存在”“子代理说完成”“已经批准”均不等于已验收。
2. **结果与非目标**：每个 Task 只有一个可验收目的；明确不会顺带做什么。
3. **决策**：区分已接受约束、随本计划接受的推荐方案、内部实施细节。
   影响行为/兼容性/预算的未决项不得藏在“实现时再说”里。
4. **配套范围**：实现、调用方、测试、fixtures、bench、测量工具、平台分支、
   CI、本 Task 报告及 ADR/架构文档一并考虑，不能只列业务源文件。
5. **验收能力**：每个 DoD 对应命令或人工检查、预期结果、证据路径和责任 Task。
   尚不存在的命令标为“待本 Task 创建”，明确创建它的文件范围。
6. **失败路径**：非法输入、部分失败、恢复、取消、溢出、序列化旁路、
   队列/内存上界、平台不支持；不是只有 happy path。
7. **执行顺序**：依赖交付物、共享文件所有者、可以并行的叶子任务，以及
   谁做最终整合和独立验证。并行不是默认要把整个架构交给子代理。

计划不是保证零 bug，而是保证可预见的设计与工具缺口有负责人、有范围，
不会在执行末尾才变成新的审批要求。

## 2. 一次批准的含义

每份执行计划标注 **Plan ID / Revision / Task 集合 / 推荐决策 / 外部操作 / 终点**。
用户对刚呈现且唯一明确的计划说“按照你的计划来”，即接受这些内容；记录一次即可。
不要求用户复述 ID，也不再逐项询问 Task、ADR 落字、文件清单细化或 Luna 分发。
只有同时存在多个无法辨明的计划时，才问一次要执行哪份。

- 批准后，Codex 可以在计划内先补齐技术设计、测试与工具，再按 DAG 连续实施。
- **批准不等于 Ready，更不等于 Done**。Ready 是 Codex 自己确认依赖和执行契约
  已经具备；Done 是独立验证完成。Ready 检查失败时先在计划内解决，不找用户补签。
- 推荐决策的实质发生变化，才形成计划增量；不要通过更新 Revision 偷换已批准方案。
- 只要求“制定/审查/明确计划”不批准其业务实现。本次明确任务的要求仅授权文档工作。
- 默认本地交付；commit/push/PR/merge、远端设置、发布、费用或不可恢复操作必须在
  计划中明确列出才属于它的授权。已有明确授权继续有效，但不得猜测目标或绕过保护。

## 3. 执行时自行处理与真正暂停

| 情况 | Codex 的动作 | 是否重新问用户 |
|---|---|---|
| 测试失败、lint、实现 bug | 在原范围修复并重跑；不弱化测试 | 否 |
| 已列模块内增加私有 helper/test/fixture，或已列工具新增用例 | 更新实际文件清单并实施 | 否 |
| 已列公共接口的签名细化、配套调用方适配 | 主代理先写 ADR/契约，再实施和验证 | 否，前提是不改变计划已述语义 |
| Luna 不适合、结果不合格或不可用 | 缩小叶子任务；一次有界返工后由 Codex 接管 | 否；模型不可用时不偷偷替换指定外部 provider |
| 需要修改未列模块但只是遗漏的必要配套工作 | 先判断是否仍在已批准配套范围；在范围内自行补齐 | 不按文件名机械加审批 |
| 需要新增产品行为、改变已定语义/兼容性/预算，或新增未授权外部影响 | 给出最小计划增量、影响与推荐选择 | 是，仅问新增决策 |
| 与 Master Spec 冲突 | 写 CP，停止冲突部分 | 是；CP 不是普通文档修改许可单 |
| 已穷尽范围内处理，仍有真实权限/环境/依赖阻塞 | 保留证据，说明确切缺失条件 | 是；不假报完成 |

“停止提交失败结果”不等于“停止修复并等待用户”。独立且已批准的工作可以继续；
依赖失败结果的 Task 不得绕过。涉及已接受 ADR 的语义变更先记录 ADR；若变化不在
批准计划中，再提交决策增量。常规架构/性能文档同步不需要 CP。

## 4. Benchmark 也必须是一份可执行契约

每项指标先写明：工作负载、单位、计时区间/对象存活区间、基线、采集工具、
样本数与 warm-up、硬件/build、正确性断言、证据位置、gating 或 diagnostic。

- 端点 RSS、进程生命周期峰值、区间峰值增量、堆大小是不同指标，不允许替换名称。
- 复用 [ADR-0020](adr/ADR-0020-benchmark-memory-measurement.md) 的 macOS 工具时，
  先确认**这个新工作负载**有 adapter；已有工具不代表新 Task 已可测。
  adapter/CLI/probe/平台测试和必要 manifest 调整计入该 Task。
- 无对应系统可以 N/A；测量工具缺失、失败或不支持应记为未完成/不可用，
  不能把必测项改成 N/A 来完成 Task。保留失败样本，不偷偷重试筛选。
- 长跑先做短 smoke，估计墙钟与磁盘/内存成本，再跑完整目标；预估不冒充结果。
  不因预估慢而缩短 10 年、减少 NPC、跳过行为或放宽预算。
- 性能采集与编译/其他 agent 的重负载串行。CI correctness smoke 不冒充 M5 测量。

## 5. 交付与自动继续

每个 Task 报告只需包含：实际改动文件、实际命令/结果、DoD 逐条证据、benchmark
或有依据的 N/A、敏感改动、限制，以及已批准计划中的下一个 Ready Task。
不用创建一套重复审批文书。子代理报告不是验收证据；主代理必须检查 diff，并独立
运行相关检查。完整计划的终点、里程碑确认和下一 Phase 是不同边界，不自动跨越。

## 6. 历史计划与上下文预算

默认入口为 [当前进度](CURRENT_PROGRESS.md) 和 [Task 索引](TASK_INDEX.md)。完成的计划保留全文，但只在索引写状态、结果、现行 ADR、证据/源码身份、限制和重开条件；不在每份后继计划复制旧全文，不递归读取全部历史依赖。

当前任务读取：四份强制规范 → 当前进度 → 当前 Task 与直接相关 ADR/源码/测试。历史批准有疑问、接口契约变更、回归排查或复查旧测量时才打开相应历史全文。索引不替代权威规范；同一上下文已完整阅读且未改变的文件可以复用。新会话仍完整读取强制规范。不会自动清除已经占用的聊天上下文，也不保证固定百分比 token/费用节约。
